# Release v2.9.0
Image: mybadreligon/maintenhance:2.9.0   (built by the release workflow on the push to main that set version 2.9.0; also tagged 2.9 and latest)
Short: Add list builder, email intake, AI convert
Long: Build with AI takes lists and files, reviewed one by one with AI questions. Emailed or forwarded texts become draft work requests via a Cloudflare Worker. Convert-to-work-order has a Build with AI button. Built P-1, P-2, P-3.
Release commit: the main commit that sets version 2.9.0 (short hash in the release report)        Tag: created by the workflow with gh release create v2.9.0 --target $GITHUB_SHA (nothing is pushed from the authoring session)
Type: minor (new features, new endpoints, one new dependency: mailparser)
Update: later
Port: 8040 (host = container; existing assignment; second instance maintenhance_twl is 8041)   Exception: none
Public hostname: unchanged (existing deployment)        Needs Caddy route: no. For email intake the app hostname must be reachable from Cloudflare's Worker (it already is through the Cloudflare Tunnel); if Cloudflare Access protects it, add a Bypass policy for the path /api/inbound/email.
New or changed env vars: INBOUND_EMAIL_SECRET (secret, 16+ characters; blank = email intake off and the route answers 404), INBOUND_EMAIL_ADDRESS (display only, e.g. requests@hoffmanhouse.ca). Both are optional and already wired in docker-compose.yml and deploy/compose.yaml; add them to the stack .env to use email intake.
Data: /data (SQLite database) and /files (photos, nightly snapshots); folders already exist. Migration: yes, additive at start-up: column users.alt_emails (default '[]') and table inbound_requests. Reversible: yes, a downgrade to 2.8.1 still starts (the extra column and table are ignored); restoring the pre-update data copy is also fine. The image runs as root, so there are no owner requirements on the host folders.
Resources: not measured; the email route parses one message at a time (limit 10 MB) and calls Gemini once per message. No compose limits recommended.
Healthcheck: GET /healthz on $PORT -> 200 {"status":"ok","version":"2.9.0"}; 503 {"status":"error",...} if the database cannot be read. Unchanged from v2.8.x (node command, start period 30s).
Verify after deploy: (1) docker ps shows maintenhance healthy; (2) wget -qO- http://127.0.0.1:<PORT>/healthz returns {"status":"ok","version":"2.9.0"} (vm101 has wget, not curl); (3) sign in, open Work Requests, open a request and press Convert to work order: the Build with AI button is there (needs GEMINI_API_KEY); then Work Orders > New work order > Build with AI shows the "This is a list" checkbox. Only if email intake is set up: from your registered email send a message to the request address and confirm "From email and text" appears on Work Requests within a minute.
Email intake setup (optional, once): (a) put INBOUND_EMAIL_SECRET=<openssl rand -hex 24> and INBOUND_EMAIL_ADDRESS=requests@hoffmanhouse.ca in the stack .env and redeploy; (b) in the Cloudflare dashboard follow the steps at the top of deploy/inbound-email-worker.js (Email Routing on, create the Worker with APP_URL and the INBOUND_SECRET secret, routing rule for the address); (c) in the app, My account > Alternate sender addresses: add your phone's gateway address (for example 5195551234@msg.telus.com) so forwarded texts are accepted; (d) send a test email and forward a text.
PWA: unchanged in structure. Install checks, layout checks at 390x844, 768x1024 and 1440x900, and Lighthouse were not run for this release; the new screens were checked only at 1440x900 in a headless browser against a mock server. Cloudflare Access bypass for manifest, service worker and icons: not checked; confirm it is in place.
Docker build: not run locally (no Docker daemon in the authoring session); first build is the release workflow run, which now also installs the new mailparser dependency. The frontend compiled with vite build, backend files pass node --check, and the email route was exercised against stubbed database and AI modules (8 checks); nothing was run against real Gemini, a real Cloudflare Worker or the real database.
Rollback: previous image tag 2.8.1 (the first image under mybadreligon/maintenhance), or the pinned rollback digest of the running image. Data restore needed: no
Known issues: the AI list builder and email draft were not tested with the real Gemini service, so prompts may need tuning; the email "Sender not verified" tag depends on Cloudflare adding an Authentication-Results header; the image still runs as root without tini and has no SIGTERM handler; the service worker cache name is not versioned; the in-app changelog shows Short and Long lines raw (P-6, P-7, P-8, P-11 in docs/pending-changes.md). Training guides were not regenerated for this release.
