Update: later

Long: Back now closes pop-ups, then returns to the previous screen (web, PWA, Android). New opt-in push notifications: assigned, due or overdue, alarms, new requests; per-user toggles. Android app notifications on (P-28, P-29).

Port: 8040 (host = container; existing assignment; second instance maintenhance_twl is 8041)   Exception: none
Public hostname: unchanged (maintenhance.hoffmanhouse.ca)        Needs Caddy route: no
New or changed env vars: all optional: PUSH_ENABLED (false turns push off), VAPID_PUBLIC_KEY, VAPID_PRIVATE_KEY, VAPID_SUBJECT (blank = a key pair is generated once and stored in the database). Names added to docker-compose.yml and deploy/compose.yaml. See v2.11.0 for the AI_* names.
Data: /data (SQLite) and /files (photos, snapshots). Owner is UID 1000 / GID 100 as before. Migration: schema 10 -> 11 (adds tables push_subscriptions and push_sent and four push_* columns on users); the existing pre-migrate backup copy runs first. Rollback to 2.11.x keeps working (extra tables/columns are ignored) but restoring the pre-migrate copy is the clean way back.
Resources: unchanged plus one 5-minute timer (a small database read) and web-push (about 1 MB of dependencies).
Healthcheck: unchanged. GET /healthz on $PORT -> 200 {"status":"ok","version":"2.12.0"}; 503 if the database cannot be read.
Server stack note: the live stack uses this repo's docker-compose.yml (data paths from the stack .env). It now also carries PUSH_ENABLED and VAPID_* names (blank values are fine), so the hands-off updater is expected to return CONFIRM for maintenhance_home. maintenhance_twl (port 8041) needs its own separate update. Push messages leave the server to the browser vendors' push services (fcm.googleapis.com, updates.push.services.mozilla.com, etc.): outbound HTTPS must be allowed.
Verify after deploy: (1) docker ps shows maintenhance healthy with a new start time; (2) wget -qO- http://127.0.0.1:<PORT>/healthz returns version 2.12.0; (3) sign in, open Settings -> Push notifications, tap Turn on for this device, allow, then Send a test: a notification arrives; (4) docker logs maintenhance shows a push_sent line (event=test) and no message text; (5) on a phone or laptop: open a work order, press Back (pop-up closes), press Back again (previous screen).
PWA: installable as before; the service worker gained push and notification-click handlers and its cache name is maintenhance-shell-v2.12.0, so phones show the "Update available" bar once. Layouts: the new settings card uses the existing form styles; back navigation was checked in a browser at desktop and phone width (390 x 844); the new card was not visually reviewed on a phone.
